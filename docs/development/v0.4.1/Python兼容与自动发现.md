# v0.4.1 候选：Python 兼容与自动发现

日期：2026-10-09。基线：v0.4.0 发布后的 main `a2aeff5`。本轮不合并、不发布正式版本，不替换 v0.4.0 资产。

## 问题及修复范围

用户在另一台设备安装 Python 3.13，却无法启动。旧控制器只搜索 Python311/312 目录和 `py -3.11/-3.12`，C# 探测与 Python 准备脚本均只接受这两个版本；不支持版本、无法启动与探测超时都返回空结果。仅手动选择 3.13 路径不能绕过此限制。

本轮集中管理支持矩阵，补齐自动发现、明确失败原因、3.13/3.14 的原生依赖锁与 Windows 验证。未修改科学参数、模型配置、POTCAR 确认规则或远端执行逻辑。

## 支持矩阵

| Windows x64 标准 CPython | 处理方式 |
|---|---|
| 3.11、3.12 | 保留原锁文件，进行回归 |
| 3.13、3.14 | 新增独立锁文件；真实解释器安装与服务联调通过后进入候选 |
| 3.15 | 能识别并解释阻断；暂不允许自动安装完整应用依赖 |
| 未知后续版本、32 位、ARM64、自由线程、预发布版 | 不冒充已验证支持，给出原因 |

唯一版本策略来源为 `launcher/python-support.json`；C#、Python 准备脚本、运行检查及设置页读取同一文件。测试要求每个 supported 项具有对应锁文件和 Windows CI 条目。

### 3.15 的真实阻断

2026-10-09 对官方 PyPI 执行 Windows x64、CPython 3.15、仅二进制的运行依赖解析，首先在 `PyYAML>=6.0` 失败。官方包元数据核查结果：

| 包 | 核查版本 | Windows CPython 3.15 wheel |
|---|---|---|
| PyYAML | 6.0.3 | 无 |
| pymatgen-core | 2026.10.2 | 无 |
| spglib | 2.7.0 | 无 |
| NumPy | 2.5.3 | 有 |
| SciPy | 1.18.1 | 有 |

来源：[PyYAML](https://pypi.org/project/PyYAML/6.0.3/#files)、[pymatgen-core](https://pypi.org/project/pymatgen-core/2026.10.2/#files)、[spglib](https://pypi.org/project/spglib/2.7.0/#files)、[SciPy 发布记录](https://scipy.org/news/)。这些是本次核查时的情况，不是永久限制。

不强迫用户安装编译工具，不为满足新 Python 而大幅降级科学依赖。后续官方包补齐后，用真实 3.15 正式版运行 `launcher/tools/lock_runtime.py`，增加锁文件、CI 和完整安装/业务回归，通过后再修改策略为 supported。只有 RC 可用时不能据此宣称正式版已验证。

## 自动发现及错误语义

1. 手动路径优先且独占。失效时说明该路径问题，并提示点击“自动检测”；不擅自替换用户指定环境。
2. 自动模式依次检查项目环境、已激活环境、PATH、PEP 514 注册信息（当前用户/机器、32/64 位视图）、常见 Python 目录和 Conda 登记环境；路径规范化去重，不扫描全盘。
3. 再尝试 `py` 的策略内版本选择器。禁用 Python Install Manager 自动下载；原有允许安装的环境变量也不传入探测进程。
4. 普通 WindowsApps 的 Python 执行别名不当作解释器；真正注册的 Store 安装仍可被发现。
5. 每个候选最多探测 10 秒，整体发现约 60 秒预算（正在进行的单次探测最多再完成一次）；探测进程归入既有 Windows Job，取消/超时只清理所属进程。
6. 区分版本、架构、自由线程/预发布、无法启动、信息损坏和超时。失败详情保存在应用本地日志，界面优先显示已发现但不支持的版本及原因。

“自动检测”按钮清空手动路径，保存并启动后执行检测；设置页显示上次启动采用的基础解释器版本及路径。支持列表从策略读取。

## 依赖与测试约定

- 新锁使用真实 Windows 3.13/3.14 解释器解析，避免跨版本解析时环境标记取错宿主版本。
- 自动安装只访问官方 PyPI，保持精确版本、SHA256、仅 wheel、应用专用 venv；基础解释器不安装项目依赖。
- 成功标记、锁文件哈希和模块导入共同决定是否复用；取消或失败后可重试，不改变进程归属、凭据隔离和代理处理约定。
- C# 用真实进程测试版本筛选、中文/空格路径、重复路径、手动失效路径、PEP 514 路径解析、Conda 登记、超时和格式错误；注册表夹具只使用临时测试键并清理。
- Windows CI 覆盖 3.11/3.12/3.13/3.14：构建、准备逻辑、首次真实安装与复用、控制器回归、真实本地三服务、核心应用合成数据回归。
- pytest 单独放入测试工具目录，不加入产品依赖锁、不安装进应用专用环境。
- 应用测试覆盖结构/工作流 ZIP、诊断规则与合成 POTCAR 拼接；阻断外部服务请求，不访问用户真实凭据、赝势和超算。

## 候选验收与后续

1. 完成本地验证、PR 和 CI，产出带完整前端及 EXE 的 Windows 候选 ZIP。
2. 用户在原来只有 Python 3.13 的设备上完整解压，确认安装目录，Python 留空，启动。首次需要直连官方 PyPI。
3. 复查启动设置显示的版本/路径，打开工作流、诊断、本地赝势及智能设置；重启应复用环境。
4. 用已有 3.15 或失效手动路径验证提示，不应再笼统声称 Python 未安装。
5. 用户复测通过后再审阅合并与 v0.4.1 发布；3.15 的依赖阻断不应包装成支持成功。

验收边界：软件回归通过不等于真实模型、MP、SSH/HPC、VASP 科学结果或另一台设备已验证。
