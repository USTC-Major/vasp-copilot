## 需求与覆盖关系

PR #65 实现了独立计算卡，但将任务入口收进“分析管理”，弱化了用户要求保留的独立任务层。本次恢复“任务列表 → 任务详情 → 计算卡”两层组织。每个任务独立管理导入构型、参考、卡片和结果；仅同一任务内的卡共享样本。吸附能和材料形成能分别创建任务，不混合。

沿用 collections 的记录、稳定 ID 和存储隔离，不新建第二套任务模型；这里的计算任务是能量后处理任务，不是超算提交作业。原 `?collection=` 链接继续打开对应任务。

## 兼容接口合同

继续使用 `/api/v1/toolbox/postprocessing/energy/collections`。

- 列表新增 `sample_count`、`card_count`，原记录字段和 ID 保持。
- `PUT /collections/{ident}/title` 接收 `expected_revision` 和 `title`，返回现有 `collection` 包装；仅更新任务标题、修订和更新时间，不改变科学确认、卡片锁与结果。
- `DELETE /collections/{ident}?expected_revision=N`：新版必须传修订号，陈旧请求返回409；省略参数保留旧客户端兼容。删除只针对校验后的软件任务目录，异常目录内容拒绝处理，不追随来源路径。
- 现有 `?collection=<ID>` 前端链接直接进入任务详情；无该参数时显示任务列表，不自动进入最近任务。

独立任务不等于新的超算作业。显式导入已有作业结果或缓存只创建本任务自己的样本记录，不使不同任务共享可变状态。
