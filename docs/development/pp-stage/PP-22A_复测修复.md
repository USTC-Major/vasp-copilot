## 必须保持的边界

- 新分析只选一种类型，可有多个目标。不同参考条件分别建分析。旧混合类型记录保留，显式按类型生成新记录，不静默覆盖。
- 锁定由后端执行，解锁不等于取消全部确认。科学修改按实际依赖失效；添加目标不能清空无关样本事实核对与风险接受。
- 角色识别采用确定性规则并提供依据。缺少目录信息时不得臆造；歧义不强猜，不以最低能量判断参考，不自动接受风险或覆盖人工角色。
- 删除仅涉及当前分析样本及关联，不删除原始文件、任务文件、其他分析或共享缓存。删除参考须说明影响，缺少参考时阻止计算。
- CSV 是辅助数据入口，OUTCAR 用户直接批量导入。数据表回导不继承来源验证、确认锁定或科学收敛结论；原值与人工修订来源保持明确。
- 不改能量公式、既有解析完整步原则或方法支持范围；不增加 LLM、远端脚本或真实外部连接要求。

### 浏览器集成发现

首个真实浏览器流程发现定向测试未覆盖的序列：创建分析后，前端先持久化默认空参考组，再批量导入。后端把新组的空引用误判为人工清空，自动分配因此被人工保护规则阻止。四份同名 OUTCAR 已正确解析，但角色未能填入。本次保留失败截图、集合快照和请求证据，补实际 create → configure 默认组 → 批量导入 → autofill 的回归；修复后只重新验收该受影响起点及尚未完成的后续流程，不把首次失败记录为通过。

补修将空字符串引用按空值比较，新默认组不再被推断为人工清空；显式人工标记以及既有绑定被清空仍受保护。新增实际 API 序列和既有人工清空保护两项首次通过（2 passed），第二批后端累计11个唯一用例。仅后端 store 和对应测试变化，无需重复构建或导出 OpenAPI；通过专用停止文件重启14671，复用隔离数据继续验收。
