## 三、拟定产品方案

### DG-1：SCF 双视图与证据正确性

同一离子步并列展示两幅图，窄屏上下排列，选择离子步和查看区间联动：

- **总能量趋势**：保留可含负值的真实总能量，默认线性坐标，提供全程／末期和区间缩放；不直接对带负值的总能量取普通对数。使用合适有效位数和 tooltip，避免早期异常尺度遮蔽末期细节。
- **电子步变化量**：以绝对能量变化的对数纵轴为主，tooltip 保留带符号原值与来源。有 OSZICAR 原始 dE 时使用原值；只有 E 序列时可按相邻实际电子步计算，但必须标为派生值，不跨离子步、重启边界或缺失步相减。
- 已有 d epsilon 在能量变化图中可作为单独、明确标注的序列；不能用总能量差代替其数值。零值、缺失、非有限值和输出精度不足分开处理，不为对数图伪造小正值或画成“已收敛”。
- 横轴默认覆盖已有数据；NELM 只有从实际输入／有效参数读取时才显示，未知不硬填200。修正参考线配置，并在上限位于当前视区外时用说明展示，不把空白区域强行扩到上限。
- EDIFF 参考线来自有效输入／输出并标来源，缺失不得冒称用户使用了某阈值；EDIFF=0 的固定步数语义需单独处理。
- 删除“能量下降等于趋于收敛”的暗示。页面区分“变化趋势”“计算报告的收敛状态”“证据不足”，不从单条曲线直接签发科学正确结论。

验收：大幅初期变化＋极小末期变化、振荡、正负能量、零差值、单点、断档、多离子步、缺失阈值及实际NELM、EDIFF=0；核对后端原值到图表与tooltip的一致性。

科学依据：[VASP EDIFF](https://vasp.at/wiki/EDIFF)同时涉及自由能与能带能量的电子步变化；一条能量下降曲线不是完整停止条件。

#### U-4数据与显示合同（2026-10-02）

- 电子记录保留原始 E、dE、d epsilon、原始文本、状态和 OSZICAR 行号；新增 block_id 区分重启后重复的离子步编号，无汇总的编号标为推断。兼容旧 energy 字段。
- 只有 dE 原始列真正缺失、同块且相邻实际电子编号的两条有限 E 才派生差分；原始零值或无效值不被替换。派生差分保留来源和输出分辨率，不能由打印精度不足推断收敛。
- 两图由同一块选择和同一范围缩放控制；末期指当前块最后20条真实记录。总能量使用线性坐标；变化量使用绝对值对数坐标，提示保留符号。零值、无效、精度不足的点不伪造正数，折叠明细提供逐条核对。
- EDIFF/NELM 保留来源、行号、原文及冲突。有效 OUTCAR 回显优先于 INCAR，输入输出不一致明确说明；多个不一致输出回显不选择任一阈值。无法归属所选块时仅作为运行输出参考或未核实的输入参考。
- EDIFF=0 为固定步数语义；NELM 位于观测范围外只文字说明。明确电子停止文本单独展示且保留未归属状态，不修改确定性规则、不把图线当作电子／离子收敛结论。
- 既有 MD 的 N T=... F=... 汇总归属支持未在本轮扩展；不能把推断编号宣称为真实 MD 离子步。科学收敛判断、磁矩重构及真实计算验证不在 U-4 本轮范围。

依据：[OSZICAR 列定义](https://vasp.at/wiki/index.php/OSZICAR)、[EDIFF 定义](https://vasp.at/wiki/index.php/EDIFF)、[NELM 定义](https://vasp.at/wiki/index.php/NELM)。

### DG-2：以 MAGMOM 为参考的磁性排列对照

首批围绕**共线计算**建立可解释的排列对照，不把任意图形直接贴成“铁磁／反铁磁已确认”。SOC／非共线仍可展示有来源的原始数据和限制，但向量排列判定作为后续独立范围，不提示用户为了适配工具而改成共线重算。

先打通数据：

1. 按 POSCAR／已解析结构的原子顺序，关联元素、原子索引、必要位置、展开后的 MAGMOM 和最终局域磁矩；检查数量、顺序、输入输出是否对应。不得按元素重新排序后错配同种元素的原子。
2. 区分“输入 MAGMOM 参考”“真实初始化信息”“最终/最近一次局域磁矩”。重启时输入 MAGMOM 未必等于真实初始磁矩，故不得一律将其称作实测初始值。
3. 缺少 MAGMOM、结构、逐原子投影或最终输出时明确不可比较，不能用0填补缺失值。未收敛／截断输出标为暂态证据。
4. 单胞总磁矩如有直接输出则独立展示；逐原子投影之和不直接当作全胞精确总磁矩，保留投影来源与定义。

主界面改为“排列概览＋依据＋可筛选明细”：

- 概览优先回答“相对于输入参考，哪些原子间的同向／反向关系保持、哪些发生变化、哪些磁矩明显衰减、哪些证据不足”。
- MAGMOM 初始正负两组只作为参考分组，不自动宣称就是晶体学／磁性子晶格。非零局域磁矩符号一致、正负抵消等仅描述为有依据的排列特征／候选磁态；复杂 AFM、亚铁磁或不同 AFM 图样需结构和进一步证据。
- 不能用总磁矩近零断言反铁磁，也不能把所有符号翻转都判错。共线无外场等适用条件下，所有磁矩整体翻转但相对排列保持应单独标为整体反转；局部翻转与磁矩衰减分别列出。
- 设定并显示近零与变化阈值，先冻结来源、容差及适用条件；不将一个任意阈值用于所有体系的科学结论。
- 下方按元素、MAGMOM参考组、变化类型筛选；表格包含原子索引／元素、输入参考、输出局域磁矩、差值、排列变化与证据。保留可缩放的逐原子图，颜色和图例一一对应。
- “符合输入参考”只表示该次计算排列与用户输入的关系，不代表实验磁态或基态已验证。判断磁性基态通常需要比较候选态等额外证据，本批不自动启动此类计算。

验收：同向保持、补偿的正负排列、局部翻转、整体反转、幅值衰减、诱导弱磁矩、多元素／同元素不同位点、大量原子、缺失MAGMOM、原子数不符、截断结果、重启以及SOC／非共线保护。需独立科学逻辑审查，不能只验证柱子能显示。

依据：[VASP MAGMOM](https://vasp.at/wiki/MAGMOM)、[VASP 自旋极化体系教程](https://vasp.at/tutorials/latest/bulk/part3/)。输入参考、重启语义及输出局域磁矩应在报告中区分。

### DG-3：诊断解释接通统一模型配置

建议继续遵守 Toolbox 独立、AI 可选的解耦边界：确定性诊断不依赖模型；解释／追问复用智能模式已有配置和调用能力，通过受控接口取得回答，不在 Toolbox 新建第三套密钥或直接导入 AI 内部模块。

具体设计先冻结，不用复制密钥到旧 JSON 当修复：

- 诊断页面的可用状态和实际解释接口使用同一来源；仅展示“已配置”不能表示连接测试通过。
- 区分加载中、未配置、主动关闭、AI服务不可达、状态读取失败、模型调用失败、可使用；失败不能落成“未启用”。
- 设置保存／替换／清除后，状态及时失效刷新，实际解释使用对应新配置；停用或删除密钥后不得回退旧明文继续调用。
- 旧诊断配置的迁移／冲突处理需复用已有凭据规范，保留用户选择，不静默覆盖更近的智能模式配置。主产品只保留清楚的一处设置入口。
- 模型输入限诊断所需文本及证据，回答对问题和来源可追溯；不把自然语言解释变成确定性诊断或自动执行入口。
- AI未启动时原报告、图表与人工修复信息仍可用；“解释不可用”不拖垮诊断页面。
- 状态读取不偷偷发送模型请求；真实连通／质量测试另行明确预算。

验收：配置读取与实际调用同源、AI缺席、开关关闭、状态错误、保存／清除、超时与失败、无假成功回复、配置变化后缓存刷新；先用受控模型测试，再在授权范围内做真实调用。当前仅确认配置分裂，未验证真实模型回答。

### DG-4：修复建议的状态与人工流程

将“是否能生成候选”“用户是否审阅”“是否已下载”“是否已应用”分开表达，首批只实现手工应用路径，不新增应用按钮或远端写入。

| 真实情况 | 页面文字与行为 |
|---|---|
| 没有建议修改／无可用规则 | “暂无可生成的参数修改”；说明覆盖限制或无需修改的真实原因，不显示空diff与“需确认” |
| 有问题但证据不足 | “需补充信息”；列缺少什么文件／参数及补充后能判断什么 |
| 有具体建议但不能安全生成 | “建议人工处理”；给相关问题、依据、拟议变化与不能生成原因，不伪装成批准后即可生成 |
| 已生成可审阅候选 | “候选修复已生成，应用前请审阅”；列参数旧值→新值、原因、风险、关联问题与文件差异；允许下载 |
| 已下载 | 仅表示文件已取得，不标“修复完成／已应用” |

每份候选附明确人工步骤：核对是否适用于当前目标→备份原输入→对照差异→由用户应用→需要时重新诊断／计算。说明不自动覆盖输入，不自动重启作业。保留 `INCAR.fixed`、差异及人工说明的已有交付能力，确认最终下载入口是否真的有文件，不能仅靠 recommended_fixes 非空启用下载。

后端状态须来自 fix_status、有效changes/diff、真实候选文件和依据；无可用改动时不要构造一张等待确认的空卡。保持白名单和静态复核约束，不以改善提示为理由放宽自动修复范围。原始内部类型 parameter_patch 在主视图改为可理解中文，内部值可留详情。

验收：无问题、问题存在但无自动规则、缺INCAR、门禁拒绝、有效候选、空diff、文件缺失、下载成功和失败；均没有含糊／重复“需确认”，没有未经操作的“已应用”。

#### U-6兼容接口与复测（2026-10-02）

保留既有 `FixStatus` 三态以及 `safe_to_generate`、`requires_user_confirmation`、`changes`、`diff` 字段语义。结果读取与运行响应追加以下信息，下载端点使用同一核验函数：

| 字段 | 含义 |
|---|---|
| `fix_available` | 当前推荐与实际三文件候选均通过核验，才为true；页面仅据此启用下载 |
| `fix_reason_code` / `fix_reason` | 诊断级原因码与中文说明；空推荐也返回 |
| `fix_manual_steps` | 对应当前状态的补充证据、人工处理或候选审阅步骤 |
| 推荐项的 `reason_code` / `reason` / `manual_steps` | 每份推荐的原因与步骤；多候选时逐项说明，不能因另一份可用而把失效项标为就绪 |

原因码对应：`candidate_ready`为已核验候选；`missing_incar/missing_value`为需补信息；`no_issues/no_rule/no_changes`为暂无可生成修改；`manual_review/safety_rejected/candidate_missing/candidate_invalid/generation_failed`为人工处理或重新生成。原因码供接口使用，主界面展示中文。旧客户端字段保持兼容；新页面遇到缺少权威状态的旧响应保守禁用下载，提示刷新核验。

候选继续交付 `INCAR.fixed`、`parameter_diff.json`、`APPLY_MANUALLY.md`。核验推荐身份、有效参数变化、文件差异及三文件一致性，每次重跑替换旧候选；孤立、缺失、损坏或不匹配文件不能进入ZIP。不会覆盖原输入。对于当前解析器无法安全处理的分号多参数行、重复移除后仍残留有效值等情况，拒绝交付并要求人工处理；不扩修复白名单、不重构解析器。

建议复测：

1. 正常候选：比较页面旧值→新值、文件diff、ZIP参数JSON和人工说明；确认原INCAR未变，下载后仍只表示候选已取得。
2. 无问题、缺INCAR、无规则、缺新值及安全拒绝：原因明确，没有空diff、重复“需确认”或可用下载按钮；报告仍可取回。
3. 生成异常、候选丢失/损坏及重跑变为不可生成：原诊断保留，旧候选不可下载；读页面后候选失效的下载请求返回可理解错误，刷新状态可恢复到正确显示。
4. AI关闭或状态读取失败：修复建议及报告下载独立可用。在宽屏与375px窗口检查表格、差异、人工步骤和错误恢复。
