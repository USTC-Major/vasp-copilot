## 三、实施合同

### 3.1 DFT+U 两种计算形式

| 形式 | 用户界面 | 写入与确认规则 |
|---|---|---|
| Dudarev，LDAUTYPE=2 | 按元素／轨道填写 Ueff=U−J，单位 eV | 新的 Ueff 输入写为 LDAUU=Ueff、LDAUJ=0；实际数值与形式同时出现在确认摘要、计划及 INCAR |
| Liechtenstein，LDAUTYPE=1 | 按元素／轨道分别填写 U、J，单位 eV | U、J 原值写入对应数组；不以 Ueff 静默替代，不宣称与 Dudarev 等价 |

共同要求：

- 在独立字段中保存形式和输入含义，不能靠界面标签推断；沿 POSCAR 元素顺序生成 LDAUL/U/J。
- 旧请求不带形式时保持原 LDAUTYPE=2 行为；旧 U/J 记录保留原值与来源。若在新界面转换为 Ueff，显式显示 U−J 的计算结果并重新确认，不静默改写历史产物。
- 切换形式或修改元素、轨道、数值后撤销对应旧确认；最终确认快照、生成请求和预览必须一致。
- 非有限数、缺少所需参数、重复元素、非结构元素及不支持形式明确拒绝；异常数值提示延续既有政策，不擅自给科研参数兜底。
- 参数编辑补丁不得让页面宣称的形式与最终 LDAUTYPE 脱节；存在覆盖时显示最终值和来源，再确认。
- 首批不增加 LDAUTYPE=3/4，不替用户判断体系应取多大 U/J。

U-2 接口约定：`workflow.dftu` 显式保存 `form` 与 `input_mode`。新 Dudarev 请求使用 `form: "dudarev"`、`input_mode: "u_eff"`，条目只提供 `u_eff_ev`；新 Liechtenstein 请求使用 `form: "liechtenstein"`、`input_mode: "u_j"`，条目分别提供 `u_ev` 和 `j_ev`。元素、轨道、来源与用户确认仍保留在各条目中。新会话默认关闭 DFT+U，开启后须明确选择计算形式，不预选新的科学方法。表单切换形式时清空科学数值及旧来源说明并撤销确认，要求重新填写；不自动换算旧记录。

两个新字段同时缺失或同时为 null 表示旧版 Dudarev U/J 语义，保留旧 U/J 原值；旧请求省略 J 时沿用旧默认 0，这个默认不适用于新 Liechtenstein。仅提供一个字段、形式与输入模式不匹配、混合两种数值字段、缺少当前形式所需值均拒绝。新增元数据可能改变重新生成计划和清单的哈希，但不得改写历史 ZIP 或静默改变旧科学输入。

计划、最终确认摘要及生成包保持同一输入语义；Recipe 的 `resolved_parameters` 和 `provenance` 继续表示最终参数及来源，`modifier.dftu` 身份和层级不变。最终 LDAU/LDAUTYPE/LDAUL/LDAUU/LDAUJ 与已确认请求不一致时，生成应阻断并提供覆盖来源，需重新规划和确认。

依据：[VASP LDAUTYPE](https://vasp.at/wiki/LDAUTYPE)。该资料区分不同 DFT+U 形式；选择形式的功能不能当作参数适用性的科学认证。

### 3.2 PBE／PBE+U 能带恢复

先冻结后端能力开关与前端展示的统一规则：关闭时页面明确不可用；开启时普通计划、自然语言计划及重放生成使用同一判断。不要用前端强填 true 绕过服务端能力限制。

限定恢复内容：

1. 复现普通表单 band 请求被关闭的路径；核对 bootstrap、计划、确认、生成、下载的实际传递。
2. 明确 static → band 的前置关系及 CHGCAR 继承。若选择可选 relax，按实际最终结构建立依赖；不把 band 独立文件生成误称为上游已完成。
3. 检查高对称路径的坐标基底与实际 POSCAR 晶胞一致，记录路径约定、识别容差及必要的标准化说明。对非标准胞、超胞、识别失败给出明确边界，不只检查 KPOINTS 能解析。
4. relax 可能改变晶胞。设计时必须明确路径依据：下载时可先生成有来源的候选路径，实际用于 band 的路径须与上游完成后的结构一致；若当前产品不能可靠重新准备，则明确标记需重新生成／确认，不在旧路径上直接放行。不得静默替换科学结构或扩展成新的自动调度系统。
5. 检查 static、band 的 DFT+U 参数及 LMAXMIX 一致性；当前配方固定 LMAXMIX=4，但界面允许 f 轨道，需要覆盖 d/f 两类。DFT+U 固定电荷能带对 d/f 分别需要足够的4/6信息，相关上游 CHGCAR 也必须正确产生。
6. 核查路径分段采样数，不能把普通网格的 kppa 无说明地当作每段点数。对现有数值不合理或语义不明的情况先定合同，再修改默认值。
7. 首批对 PBE／PBE+U 之外的能带组合给出明确“不支持”或阻断；HSE06、SOC 专项、能带绘图与反折叠不随本批加入。

依据：[VASP 常规能带流程](https://vasp.at/wiki/Band-structure_calculation_using_DFT)、[LMAXMIX](https://vasp.at/wiki/LMAXMIX)、[pymatgen 高对称路径约定](https://pymatgen.org/pymatgen.symmetry.html)。后两项科学风险来自现有代码与文档对照，尚未完成全部材料反例验证，作为实施门禁而非已修复结论。

### 3.3 DAG 与 Recipe

DAG 使用一个明确的尺寸来源：外层实际节点包住整张卡片，卡片填充该节点；选中边框、点击／拖动区域、连接点和边路径依据同一节点边界。保留缩放与适配视图，移除右下角 MiniMap。覆盖长步骤名、阻塞提示和多行产出；不靠缩小文字掩盖溢出。

Recipe 每个计算步骤保留独立配置面板，主视图分为“基础与任务”“精度”“电子类型”“DFT+U”“其他修饰”“用户覆盖”。类别标签和颜色固定，DFT+U 从泛 modifier 中单列，其余修饰按名称逐项展示。未启用时可用中性说明，不伪造已选择的 Recipe。

建议颜色：精度蓝、电子类型绿、DFT+U 紫、其他修饰橙，基础／任务中性灰；用户覆盖使用独立标签。颜色是辅助，必须同时有文字，不能与成功／失败状态混用。分组基于明确字段及已知 Recipe 身份，不能按数组序号或随意匹配描述字符串。

可展开“组合与覆盖详情”保留原 selected 顺序、recipe_id／版本、选择理由、最终参数和覆盖来源。**展示分组不改变实际组合和覆盖顺序。**

### 3.4 文件说明和样品名

| 文件 | 目标示例／规则 | 保持不变 |
|---|---|---|
| KPOINTS | `KPOINTS for 01_relax generated by VASP-Copilot (kppa=1000)`；能带对应说明 line-mode | 网格、中心方式、路径点及数值 |
| submit.sh | `# Generated by VASP-Copilot (cbatch profile).`；同步其他 profile | shebang 仍为首行，调度指令与执行命令不变 |
| POSCAR | `mp-32761 SiO`；若用户改名，则以该名称替换 SiO | 晶格、元素顺序、计数、坐标与精度；原始 API ID 保存在结构来源元数据 |
| INCAR | 例如 `# VASP-Copilot | 02_static | self-consistent static calculation`；具体描述必须反映最终参数 | 原有参数序列化、数值与解析结果 |

样品名在结构上传／导入确认处和参数确认页可编辑，新界面默认使用实际元素计数得到的约化化学式。字段 `sample_name` 最多256个 Unicode 码点；在 trim 前拒绝 Unicode C 类字符和行／段分隔符，显式空字符串或普通空格回退为化学式。旧请求不提供该字段且没有可信 MP 来源时，保留原 POSCAR 标题。名称只用于说明和元数据，不用于文件路径或命令。

官方 POSCAR 注释限制为40字符；产品保守采用最多 **40个 UTF-8 字节**，仅在完整码点边界截断，保留开头的材料编号。这是产品兼容策略，不声称官方规定40字节。确认摘要展示完整样品名和实际短标题，完整名称保存到 `workflow_plan.json`；预览与 ZIP 中同一文件须一致。[POSCAR 格式依据](https://vasp.at/wiki/POSCAR)。

数字 ID 沿用已有可信 AlphaID 兼容规则。对没有可信旧数字编号的新增条目，保留官方原始编号并在页面说明，不能制造旧版编号。新 MP 导入严格检查请求与回包编号格式及别名关系，将经核验的回包原始 ID 保存为 `source_material_id`；请求 ID 留在原有 API `material_id` 和 `source_file` 中以兼容旧调用。旧 `source_file` 字符串不能反推可信来源。普通计划传入 `structure_id` 时优先读取服务端结构记录；自然语言计划要求服务端结构记录；回放沿用已缓存的请求。普通计划仍兼容内联结构，但其客户端来源声明会被剥离，不受信任。

INCAR 注释采用确定性模板，由步骤及最终参数推导，不调用 LLM。已知弛豫参数组合才写 ionic relaxation；固定离子时，ICHARG=10/11/12 写非自洽用途，ICHARG缺省或0/1/2写自洽用途，未知／冲突组合使用 `calculation; inspect INCAR parameters`。这表示参数用途，不表示已运行、已收敛或科学上适用。注释使用单行安全文本，参数正文及解析往返结果保持一致。[INCAR 注释](https://vasp.at/wiki/INCAR)、[ICHARG](https://vasp.at/wiki/ICHARG)、[IBRION](https://vasp.at/wiki/IBRION)。
