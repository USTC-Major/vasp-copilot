## 常用命令

后端先按仓库说明安装依赖，在仓库根目录运行（使用自己的虚拟环境Python）：

```sh
python -m pytest backend/tests/test_mp_natural_search.py backend/tests/test_materials_api.py backend/tests/test_mp_credentials_integration.py backend/tests/ai_mode/test_server.py -q
```

前端在frontend目录按现有锁文件安装依赖，再执行任务对应测试及构建检查：

```sh
npm ci
npm run test -- src/utils/materialId.test.ts src/components/upload/MaterialsProjectPanel.test.tsx
npm run build
npm run lint
```

这些是准备基线的检查示例，A/B的新行为必须补对应测试。通过相关检查后，不为凑数量反复跑相同套件；最终PR CI和同一集成版本回归仍须完成。只运行过模拟测试时不得填写“真实SSH/模型/VASP验证通过”。

### WI-1：文件动作等待竞态回归

U-4 的首次 Ubuntu CI 在磁盘写满故障注入后读到 `executing`，同提交重跑通过。只读调查确认既有 `wait_idle` 存在出队后、登记 active 前的假空闲窗口；重跑成功不能视为修复。

WI-1限定修复等待语义：同一 guard 内出队和登记在途计数，完整领取／执行／失败收尾／重排结束后在 finally 归还；等待条件覆盖队列、active和在途计数。不改变锁顺序、授权、预算、文件发布或持久状态规则；不通过延长sleep隐藏竞态。

定向入口为 `backend/tests/file_action_review/test_wait_idle.py`，使用 Event 固定出队到领取之间的窗口，验证等待不能提前成功，释放后才能空闲；同时覆盖拒领、异常和重排清理。新回归必须在旧实现上失败，不能只检查私有计数的数值。Ubuntu CI继续运行已有ENOSPC故障注入，确认失败终态、预算释放及不发布文件。

```sh
python -m pytest backend/tests/file_action_review/test_wait_idle.py -q
python -m pytest backend/tests/file_action_review backend/tests/file_action_integration -q
```

第二条在Windows上的跳过项不能算Linux验证通过；最终以同交付SHA的平台制品为准。本项无界面变更，不要求无目的地重做浏览器验收，不调用真实超算。
