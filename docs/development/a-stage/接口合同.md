# A 批分工接口合同

日期：2026-09-29。下列“现有”均已对源码核对；“目标接口”须由对应任务实现和验证，不能当成已经存在。

## 1. A-1：诊断解释接入 AI，保持 Toolbox 独立

### 现有可用基础

- Toolbox `GET /api/v1/diagnosis/{diagnosis_id}` 返回 `ApiEnvelope.data`。未运行完成只有ID/status；已有结果包含summary（兼容层对象）、issues、recommended_fixes、missing_evidence、next_step、provenance等。字段不存在不能填成科学上的零或成功。
- `GET /api/v1/diagnosis/{diagnosis_id}/report` 可取Markdown报告，未准备好返回错误。解释接入优先用结构化结果，不重新运行诊断。
- AI侧现有 `load_settings(secret_fields=('llm_api_key',))`、LLM工厂及明确错误处理可参照材料解释入口。禁止把FakeLLM当真实解释成功。
- `ToolboxClient.request` 固定增加`/api/v1/toolbox`前缀，不能拿`../diagnosis`等路径穿越伪装为现有客户端能力。

### 冻结的接线方向（由 A-1 实现）

1. AI提供诊断专用只读HTTP适配器：使用服务配置的`TOOLBOX_URL`，只GET固定的`/api/v1/diagnosis/{id}`；对ID做单路径段编码/校验，不接收用户URL、文件路径，不随重定向转发凭据；不导入`app.api`、诊断store或Toolbox内部运行对象。
2. 前端只发送diagnosis_id与question，AI从上述权威结果接口获取证据。浏览器不提供“可信诊断结果”替代后端记录，不由模型读取任意目录。
3. AI新增 `GET /ai/v1/diagnosis/capabilities`：读取当前AI开关、模型配置和实际provider，返回`mode:'ai'`、`enabled`、`configured`、`available`、`reason_code`。available仅表示本地配置允许尝试调用，不代表连通/质量通过。此GET不得ping模型或SSH，不回显密钥/掩码。服务失联由前端请求错误表达，不伪造未配置。
4. AI新增 `POST /ai/v1/diagnosis/explain`，JSON为`{diagnosis_id, question}`；严格拒绝额外字段，ID非空且无路径分隔符，question去首尾空白后1–4000字符。每次读取当前配置，不回退旧诊断明文配置。只解释，不调用agent执行器、生成工具卡或应用修复。
5. 成功响应：`{mode:'ai', ok:true, diagnosis_id, answer, evidence_source:'toolbox_diagnosis', context_truncated:boolean}`。answer非空；前端只有ok=true才显示为回答。不改权威诊断状态，不把模型文字写回确定性结论。错误沿用AI `{mode:'ai', error:{code,message,retryable}}` 形状和非2xx状态。
6. 缺模型、关闭、Fake、诊断不存在、未诊断完成、Toolbox失联、无效响应、超时、模型错误分别有明确码。沿用已有AI禁用码，其余按`AI_MODE_DIAGNOSIS_*`命名。前端显示重试/去设置/先运行诊断等正确下一步，不把错误字符串包装为成功answer。

### 证据与调用边界

发送模型的内容用明确白名单：summary、issues的标识/级别/描述/证据/建议、missing_evidence、next_step、修复候选的状态/变化/原因及必要计算模式。排除完整原始日志、上传内容、任意本地路径、密钥、旧llm_explanation和整套plot数组。现有Evidence嵌套字段须按实际schema投影，不能简单转储整份记录。

输入诊断内容按确定顺序裁剪，初始上限24,000字符（与现有模型上下文限制取较小者），优先保留阻断项/缺失证据；发生裁剪显式标记，模型不能宣称信息完整。诊断内容和用户问题均视为数据，不能让其中的指令改变只读范围。工具调用返回不执行；只接受可展示解释，否则报无效响应。请求次数/重试/输出上限不得超过既有模型配置，不后台持续重试。

前端新状态与实际调用同源；停用/清除后失效缓存。新解释入口替代该页面旧LLM配置弹窗和旧explain调用，链接到已有模型设置。保留旧后端路由给兼容调用，本批不删除它们、不自动迁移/复制密钥，解释为什么主页面不再使用旧配置。若用户只有旧配置，应提示到统一设置重新配置，不偷偷回退。

### 分工边界

A负责AI适配器/路由/测试和独立解释组件/API hook。总负责人负责确定性诊断及其数据合同。A接入`DiagnosisResultPage.tsx`前协调单独集成窗口，不顺便重构图表或修复卡。现有只读数据已满足最低需求，因此本次准备不新增一套Toolbox接口；确需新字段时先报告实际缺口。

## 3. B-1 与 U-3：MP身份

唯一显示规则是`frontend/src/utils/materialId.ts::formatMaterialId(raw)`。旧范围AlphaID可显示数字；无可信旧数字ID时原值保留。B不修改此函数；列表、请求、导入、缓存身份仍使用rawID。

样例：`mp-aaaabwmb → mp-32761`；`mp-hilzd → mp-3347529`；`mp-hilze`原样；已有数字原样。参考同目录测试。U-3生成POSCAR若需要后端格式化，由总负责人建立等价合同与交叉样例，不让B顺便写后端或把显示值当原始身份。

主分组顺序和色彩、未知类别策略、原顺序详情、可选字段处理见[队友B提示词](任务分工与B提示词.md)。分组只能派生新列表，不原地改变selected，不能修改后端组合顺序或科学参数。
