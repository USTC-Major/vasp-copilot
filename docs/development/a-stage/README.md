# A 批协作入口

范围：本轮测试反馈的 A 批修复。总负责人负责 Toolbox 与集成，队友 A 负责智能模式及约定交互，队友 B 负责三项限定前端。**当前仓库包含开发合同，不表示这些待修功能已完成，也不是新 release。**

## 如何开始

本次协作准备 PR 合并后，队友从最新 main 开分支，无需手工接收源码 ZIP。基线必须包含本目录和 `frontend/src/utils/materialId.ts`，并通过该 PR 的 CI；若尚未合并先等待。

首次获取：

```sh
git clone https://github.com/USTC-Major/vasp-copilot.git
cd vasp-copilot
git switch main
git pull --ff-only origin main
git rev-parse HEAD
```

已有克隆：先 `git status --short`。有自己未提交修改时先保留并报告，不执行reset/clean覆盖；工作区干净再切main、`git pull --ff-only origin main`。

每个任务单独分支，可采用 `fix/a-diagnosis-llm`、`fix/b-mp-id-display` 等描述性名称。不要两人共推同一分支；PR目标为main，提交前记录所基于的SHA和实际验证。使用自己的正常Git身份，不代写他人作者信息。是否有仓库写权限由现有授权决定；没有权限可通过fork提交PR，不为此共享凭据。

## 已具备的基础与待修问题

- 本基线纳入已有MP自然语言搜索候选：化学式无需AI；自然语言先解释、显示条件并确认，Toolbox再查询。现有严格条件不含空间群/晶系/kagome。
- 工作流材料列表已有可靠旧数字ID显示，API查询/导入保留原始ID；任务页补齐显示属于B-1。
- 诊断现有只读结果接口可复用，A-1新增AI解释接线；不需要总负责人先替A实现AI模块。
- Recipe现有layer/身份/来源字段足够B-3分类，不需为改颜色新增后端类型。
- 真实模型理解质量和完整线上筛选仍待独立验收；测试替身不等同真实模型通过。

不在本批：目录初始化、流程模板、连续/并行/自动纠错、MP空间群/kagome、VASPKIT、绘图、POTCAR新能力。禁止直接或间接使用VASPKIT生成/拼接POTCAR的规则保持。

本批所有产品改动先提PR、验证并交回执，由总负责人审查集成；不自动发布，不重打包0.3.0，不自行调用真实模型或提交HPC计算。
